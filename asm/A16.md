# A16 Assembly Reference

This document defines the architecture-specific assembly rules for A16. General source structure, symbols, expressions, sections, and data declarations are defined in the [common AthenISA syntax](syntax.md).

Instruction behavior and encoding are defined by the [A16 instruction set](../A16/02_instruction_set.md) and [A16 encoding table](../A16/04_instruction_encoding.md).

## Registers

A16 instructions may name `R0` through `R6` and `SP`:

```athe
MOV R1, R2
LDI SP, stack_top
```

`R0` through `R6` are general-purpose registers. `SP` may be used explicitly as a source, destination, or memory base, and `CALL`, `CALLR`, `RET`, `PUSH`, and `POP` also use it implicitly. `PUSH SP` and `POP SP` are not accepted.

## Values and data words

A16 expression evaluation uses signed 32-bit integers. Every `.data` initializer is stored as one 16-bit word. If an initializer does not fit, the assembler prints a warning and stores its low 16 bits.

A16 has a unified 64 KiB address space. The code region, every data declaration, and every address produced by `name(index)` must fit within it.

## Memory operands

`LDW`, `STW`, `LDB`, and `STB` address memory using a base register (`rb`) and a signed immediate (`imm5`):

```text
address = rb + imm5
```

The assembly syntax writes the immediate immediately before the base register (`imm5[rb]`):

```athe
LDW R1, 4[R2]
STB -1[R6], R3
```

The offset may be a literal or symbol. Omitting it means zero:

```athe
LDW R1, [R2]             ; equivalent to LDW R1, 0[R2]
STB [R6], R3             ; equivalent to STB 0[R6], R3
```

The complete memory operand is one token and cannot contain spaces. `4 [R2]` is not accepted.

An arbitrary 16-bit memory address normally has to be loaded into a register because it does not fit in the 5-bit offset:

```athe
LDI  R5, result
LDW R1, [R5]
```

## Control-flow operands

`JMP`, `CALL`, and conditional branches use offsets measured from the instruction after the control-flow instruction. Numeric and symbolic operands are interpreted differently:

- A numeric operand is the signed `imm11` encoded directly.
- A symbol is a target byte address, converted with `imm11 = (symbol - (PC + 2)) / 2`.

```athe
loop:
    BNE loop             ; assembler computes the relative offset

JMP -1                   ; execute this instruction again
BGE 4                    ; target is four instructions after PC + 2
```

Every symbol used by `JMP`, `CALL`, or a conditional branch is treated as a target address, including constants and data symbols.

A symbolic target must be aligned to two bytes, and its distance from `PC + 2` must be divisible by two. Otherwise, the target cannot be represented as an A16 instruction offset.

## Encoded field ranges

| Field | Valid range | Used by |
| --- | --- | --- |
| `imm4` | 0 to 15 | `SLLI`, `SRLI`, `SRAI` |
| `imm8` | 0 to 255 | `LI`, `LIH`, `ANDI`, `ORI`, `XORI` |
| `imm8` | -128 to +127 | `ADDI`, `CMPI` |
| `imm16` | 0 to 65,535 | Pseudo-instruction `LDI` |
| `imm5` | -16 to +15 | `LDW`, `STW`, `LDB`, `STB` |
| `imm11` | -1024 to +1023 | `JMP`, `CALL`, conditional branches |

If a value does not fit its field, the assembler normally prints a warning, keeps the low field-width bits, and continues. For example, `LI R1, 0x123` encodes `imm8 = 0x23`. Shift amounts are an exception: an immediate outside the valid `imm4` range is an error and is not truncated.

Truncation does not change how the processor interprets the remaining bits. `ADDI` and `CMPI` interpret `imm8` as a signed value, while the other instructions zero-extend it.

## Pseudo-instructions

Pseudo-instructions are convenient assembly operations built from real A16 instructions. The assembler expands them before generating machine code; they do not require additional processor hardware.

| Pseudo-instruction | Expansion | Emitted words |
| --- | --- | --- |
| `LDI rd, imm16` | `LI rd, imm16[7:0]`<br>`LIH rd, imm16[15:8]` | 2 |
| `CLR rd` | `LI rd, 0` | 1 |
| `INC rd` | `ADDI rd, 1` | 1 |
| `DEC rd` | `ADDI rd, -1` | 1 |

For example:

```athe
LDI R1, 0x1234
```

emits these two real instructions:

```athe
LI  R1, 0x34
LIH R1, 0x12
```

A label after `LDI` accounts for both emitted words. The assembler's `.lst` output displays the expanded real instructions.

## Instruction syntax

```athe
NOP
RET

MOV  rd, rs
ADD  rd, rs1, rs2
SUB  rd, rs1, rs2
CMP  rs1, rs2
AND  rd, rs1, rs2
OR   rd, rs1, rs2
XOR  rd, rs1, rs2
NOT  rd, rs

LI   rd, imm8
LIH  rd, imm8
ADDI rd, imm8
CMPI rs, imm8
ANDI rd, imm8
ORI  rd, imm8
XORI rd, imm8

SLL  rd, rs1, rs2
SRL  rd, rs1, rs2
SRA  rd, rs1, rs2
SLLI rd, rs, imm4
SRLI rd, rs, imm4
SRAI rd, rs, imm4

JMP  imm11
JMPR rs
CALL imm11
CALLR rs
BEQ  imm11
BNE  imm11
BLT  imm11
BGE  imm11
BLTU imm11
BGEU imm11

PUSH rs
POP  rd

LDW rd, imm5[rb]
LDW rd, [rb]
STW imm5[rb], rs
STW [rb], rs
LDB rd, imm5[rb]
LDB rd, [rb]
STB imm5[rb], rs
STB [rb], rs

LDI  rd, imm16
CLR  rd
INC  rd
DEC  rd
```
