# AthenISA Assembler

The reference assembler translates AthenISA `.athe` source files into 16-bit machine code for the Tydeus-16 core. It supports every real AthenISA instruction, labels, numeric constant expressions, and the pseudo-instructions documented in the [assembly syntax reference](../../asm/syntax.md).

## Installation

### Run with Cargo

Install a current stable Rust toolchain, clone the repository, and run the assembler from its directory:

```bash
git clone https://github.com/morsoth/athenisa.git
cd athenisa/tools/assembler
cargo run -- examples/program.athe
```

### Run a prebuilt binary

Release binaries are specific to an operating system and CPU architecture. The executable is named `athenisa-asm` on Linux and `athenisa-asm.exe` on Windows.

| System | Release package | Executable |
| --- | --- | --- |
| Linux x86-64 | `athenisa-asm-vX.Y.Z-linux-x86_64.tar.gz` | `athenisa-asm` |
| Windows x86-64 | `athenisa-asm-vX.Y.Z-windows-x86_64.zip` | `athenisa-asm.exe` |

#### Linux

Download the Linux package from [GitHub Releases](https://github.com/morsoth/athenisa/releases), extract it, and run:

```bash
chmod +x ./athenisa-asm
./athenisa-asm program.athe
```

#### Windows

Download the Windows package from [GitHub Releases](https://github.com/morsoth/athenisa/releases), extract it, and run:

```powershell
.\athenisa-asm.exe program.athe
```

## Quick start

Assemble a program and generate all available output formats:

```bash
cargo run -- program.athe --hex --sym --debug
```

## Command line

```
athenisa-asm <input> [-o <output-base>] [--hex] [--sym] [--debug] [--no-bin]
```

When running through Cargo, place assembler arguments after `--`:

```
cargo run -- <input> [-o <output-base>] [--hex] [--sym] [--debug] [--no-bin]
```

| Argument | Effect |
| --- | --- |
| `<input>` | Source file to assemble |
| `-o`, `--output <path>` | Optional base path for generated files; defaults to the input path without its extension |
| `--hex` | Generate a textual `.hex` memory image |
| `--sym` | Generate a `.sym` symbol map |
| `--debug` | Generate a `.lst` addressed instruction listing |
| `--no-bin` | Disable the default raw `.bin` output |

The input path is used exactly as written. The `.athe` extension is recommended but not required, and the assembler does not add it automatically when it is omitted.

Output options may be combined. Using `--no-bin` without selecting `--hex`,
`--sym`, or `--debug` is an error because it would produce no files.

The output argument is a base path. Its existing extension, if any, is replaced for each selected format. When `--output` is omitted, the input path without its extension is used. All three commands below write `program.bin`:

```bash
athenisa-asm program.athe
athenisa-asm program.athe -o program
athenisa-asm program.athe -o program.bin
```

### Help and version

| Option | Effect |
| --- | --- |
| `-h`, `--help` | Show command-line help |
| `-V`, `--version` | Show the installed assembler version |

```bash
athenisa-asm --help
athenisa-asm --version
```

## Output files

### Raw binary: `.bin`

Generated by default unless `--no-bin` is present. The file has no header or
addresses. Each 16-bit instruction word is stored as two little-endian bytes:
low byte first, high byte second.

For instruction word `0x190A`, the file contains bytes `0A 19`.

### Hexadecimal image: `.hex`

Requested with `--hex`. Each line contains one 16-bit instruction written as four hexadecimal digits. The file does not include addresses or a header:

```text
0000
190A
2112
```

### Symbol map: `.sym`

Requested with `--sym`. Each line contains a symbol name and its signed decimal
value:

```text
mem_off     -4
plus_one     1
entry       24
```

The name column is aligned. Entries keep their order of appearance in the source file. Labels and constants appear together because the assembler stores both as numeric symbols.

### Instruction listing: `.lst`

Requested with `--debug`. Each line contains the instruction address, encoded
word, and emitted real instruction:

```text
0000  0000  NOP
0001  1934  LI R1, 0x34
0002  2112  LIH R1, 0x12
```

The first two columns use hexadecimal values. Pseudo-instructions appear only through their expansion, so an `LDI R1, 0x1234` source line produces the `LI` and `LIH` rows shown above.

## Assembly flow

The assembler processes a source file in the following stages:

1. Read the UTF-8 source text and ignore comments and blank lines.
2. Scan the source to build the symbol table, evaluate constant expressions, and calculate instruction addresses. Pseudo-instruction sizes are included in this calculation.
3. Parse instructions using the complete label table. Resolve operands and turn symbolic branch targets into offsets relative to `PC + 1`.
4. Expand pseudo-instructions into real AthenISA instructions.
5. Encode each real instruction as one 16-bit machine word.
6. Write the selected output files.

Collecting labels before instruction parsing permits forward branches and jumps. The final instruction stream contains no pseudo-instructions; `.lst` is the most direct way to inspect that stream. Emission starts at instruction address 0 and the assembler does not add startup instructions of its own.

## Diagnostics

The assembler stops at the first hard error. Errors include unknown instructions, invalid registers, wrong operand counts, malformed literals, undefined or duplicate symbols, malformed constant expressions, arithmetic overflow or division by zero, malformed memory operands, and programs larger than the 2048-word instruction memory.

Values outside an encoded field's range produce a warning instead of an error.
The assembler keeps the low bits that fit in the field and continues. The exact
field ranges and source-language rules are defined in
[`asm/syntax.md`](../../asm/syntax.md#encoded-field-ranges).

Warnings are printed when the relevant operand is parsed. They are not stored in
an output file.

## Source layout

| File | Responsibility |
| --- | --- |
| `src/main.rs` | Command-line handling and output formatting |
| `src/parser.rs` | Source scanning, symbols, operand parsing, and pseudo-instruction expansion |
| `src/isa.rs` | In-memory instruction and register representation plus opcode assignments |
| `src/encoder.rs` | Conversion from instructions to words, hex text, and raw bytes |
