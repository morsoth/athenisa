# AthenISA Assembler

The reference assembler translates AthenISA `.athe` source files into 16-bit instruction and data memory images for the [Tydeus-16](https://github.com/morsoth/tydeus16-core) core. It supports every real AthenISA instruction, code and data sections, initialized data, labels, numeric constant expressions, and the pseudo-instructions documented in the [assembly syntax reference](../../asm/syntax.md).

## Installation

Installation with Cargo and prebuilt release packages is documented in the shared [AthenISA tools guide](../README.md).

## Quick start

Assemble a program and generate all available output formats:

```sh
athenisa-asm program.athe --bin --sym --debug
```

## Command line

```
athenisa-asm <input> [-o <output-base>] [--bin] [--sym] [--debug] [--no-hex]
```

When running through Cargo from `tools/`, select the assembler package and place its arguments after `--`:

```sh
cargo run -p athenisa-asm -- <input> [-o <output-base>] [--bin] [--sym] [--debug] [--no-hex]
```

| Argument | Effect |
| --- | --- |
| `<input>` | Source file to assemble |
| `-o`, `--output <path>` | Optional base path for generated files; defaults to the input path without its extension |
| `--bin` | Generate raw binary instruction and data memory images |
| `--sym` | Generate a `.sym` symbol map |
| `--debug` | Generate a `.lst` addressed instruction listing |
| `--no-hex` | Disable the default hexadecimal output |

The input path is used exactly as written. The `.athe` extension is recommended but not required, and the assembler does not add it automatically when it is omitted.

Output options may be combined. Using `--no-hex` without selecting `--bin`, `--sym`, or `--debug` is an error because it would produce no files.

The output argument is a base path. Its existing extension, if any, is replaced for each selected format. When `--output` is omitted, the input path without its extension is used. All three commands below write `program.hex` and, when the source contains data, `program.data.hex`:

```sh
athenisa-asm program.athe
athenisa-asm program.athe -o program
athenisa-asm program.athe -o program.hex
```

### Help and version

| Option | Effect |
| --- | --- |
| `-h`, `--help` | Show command-line help |
| `-V`, `--version` | Show the installed assembler version |

```sh
athenisa-asm --help
athenisa-asm --version
```

## Output files

### Hexadecimal image: `.hex`

Generated by default unless `--no-hex` is present. Each line contains one 16-bit instruction written as four hexadecimal digits. The file does not include addresses or a header:

```text
0000
190A
2112
```

### Data hexadecimal image: `.data.hex`

Generated alongside `.hex` when the source contains a non-empty `.data` section. Each line contains one initialized 16-bit data word. It is also disabled by `--no-hex`.

### Raw binary: `.bin`

Requested with `--bin`. The file has no header or addresses. Each 16-bit instruction word is stored as two little-endian bytes: low byte first, high byte second.

For instruction word `0x190A`, the file contains bytes `0A 19`.

### Data binary: `.data.bin`

Generated alongside `.bin` when `--bin` is selected and the source contains a non-empty `.data` section. It contains the initialized data-memory words in the same little-endian format.

### Symbol map: `.sym`

Requested with `--sym`. Each line contains a symbol name and its signed decimal value:

```text
mem_off     -4
plus_one     1
entry       24
```

The name column is aligned. Entries keep their order of appearance in the source file. Labels, constants, and data names appear together because they are all numeric symbols.

### Instruction listing: `.lst`

Requested with `--debug`. Each line contains the instruction address, encoded word, and emitted real instruction:

```text
0000  0000  NOP
0001  1934  LI R1, 0x34
0002  2112  LIH R1, 0x12
```

The first two columns use hexadecimal values. Pseudo-instructions appear only through their expansion, so an `LDI R1, 0x1234` source line produces the `LI` and `LIH` rows shown above.

## Assembly flow

The assembler processes a source file in the following stages:

1. Read the UTF-8 source text, ignore comments and blank lines, and join continued data declarations.
2. Scan the source to build the symbol table and independently calculate instruction and data addresses. Pseudo-instruction and data declaration sizes are included in this calculation.
3. Parse instructions and initialized data using the complete symbol table. Resolve operands, data addresses, and symbolic branch targets.
4. Expand pseudo-instructions into real AthenISA instructions.
5. Encode instructions and data as 16-bit words.
6. Write the selected instruction and data output files.

Collecting symbols before emission permits forward code and data references. The `.code` and `.data` address counters both begin at zero and remain independent when sections are alternated. The final instruction stream contains no pseudo-instructions; `.lst` is the most direct way to inspect that stream.

## Diagnostics

The assembler stops at the first hard error. Errors include unknown instructions, invalid registers, wrong operand counts, malformed literals, undefined or duplicate symbols, invalid section contents, malformed data declarations, invalid initializer counts, malformed expressions, arithmetic overflow or division by zero, and instruction or data images that exceed their memory size.

Values outside an encoded field's range produce a warning instead of an error. The assembler keeps the low bits that fit in the field and continues. The exact field ranges and source-language rules are defined in [`asm/syntax.md`](../../asm/syntax.md#encoded-field-ranges).

Warnings are printed when the relevant operand is parsed. They are not stored in an output file.
